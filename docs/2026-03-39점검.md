# 2026-03-39 코드 품질 및 보안 점검 리포트

본 리포트는 `apps/web_new` (프론트엔드)와 `apps/admin` (백엔드)의 린트 상태, 타입 안정성, 그리고 의존성 보안 취약점을 종합적으로 진단한 결과입니다.

## 1. 프론트엔드 (`apps/web_new`) 점검 결과

### 1-1. 의존성 취약점 점검 (`npm audit`)
결과: 총 **10개**의 취약점 발견 (Critical: 1, High: 5, Moderate: 4)
* **[Critical] swiper (v6.5.1 - 12.1.1)** ⭐⭐⭐⭐⭐
  * 원인: Prototype Pollution 취약점.
  * 조치 권고: 최신 버전으로 업데이트. (또는 `npm audit fix` 실행)
* **[High] next (v15.6.0-canary.0 - 16.1.6)** ⭐⭐⭐⭐⭐
  * 원인: Server Action CSRF 체크 우회, PPR 메모리 누수, DoS(Image Optimizer, Server Components) 등 다수의 보안 취약점 존재.
* **[High] 기타 (picomatch, minimatch, flatted, tar)** ⭐⭐⭐⭐⭐
  * 원인: 정규식 DoS(ReDoS), Path Traversal, Unbounded recursion 등.
* **권장 조치**: 
  ```bash
  cd apps/web_new
  npm audit fix
  ```
  를 통해 일차적으로 패치하고, 메이저 업데이트가 필요한 경우 수동으로 `package.json`에서 의존성을 갱신해야 합니다.

### 1-2. 타입스크립트 타입 에러 (`npx tsc`)
결과: 빌드 시 **중대한 타입 충돌 및 경로 에러** 발견
* **타입 중복 수출 (Ambiguity Error)**
  * `lib/types/index.ts` 내에서 `RisingStock`이라는 타입이 두 번 export 되어 충돌 중입니다. 하나는 `{ name, code, price, change }` 구조이고, 다른 하나는 `{ stock_code, stock_name, current_price, change_percent }` 구조입니다.
  * 영향도: `TradeRanking.tsx`, `TradeRankingSection.tsx`, `app/supply/page.tsx` 등 다수의 컴포넌트에서 Property does not exist 에러 발생 중.
* **모듈 경로 에러**
  * `.next/dev/types/validator.ts`에서 `../../../app/market/supply/page.js`를 찾을 수 없는 오류 발생 (경로 문제 또는 삭제된 페이지).

### 1-3. ESLint 코드 품질 (`npm run lint`)
결과: 77개 문제 발견 (24 Errors, 53 Warnings)
* **[Error] `useEffect` 내 동기적 `setState` 호출**
  * `app/components/layout/Header.tsx`, `LayoutShell.tsx`, `PinLockScreen.tsx`, `stocks/search/page.tsx` 등 수많은 파일에서 발생.
  * 원인: 렌더링 폭포(Cascading renders)를 유발하여 심각한 성능 저하 가능성.
  * 조치: 상태 설정을 Effect 밖으로 빼거나 구조를 리팩토링해야 합니다.
* **[Error] React Compiler Memoization 오류**
  * `app/page.tsx`, `app/settings/my-stocks/page.tsx`, `search/page.tsx` 등.
  * 원인: `useCallback` 의존성 배열에 삽입된 `session?.user?.email` 등의 값이 수동 메모이제이션 상태와 맞지 않아 컴파일러 최적화가 스킵됨.
* **[Warning] 미사용 변수 및 `any` 타입**
  * 다수의 API 라우트 (`api/supply-summary/route.ts` 등)에서 응답 객체에 의도치 않은 `any`가 사용되고 있고, 미사용 변수가 산재해 있습니다.
* **[Warning] `next/image` 미사용**
  * 성능 향상(LCP)을 위해 `<img>` 태그를 `<Image />`로 변경할 것을 강력히 권고. (예: `AdBanner.tsx`, `SingleBanner.tsx`, `profile/page.tsx` 등)

## 2. 백엔드 (`apps/admin`) 점검 결과

백엔드는 FastAPI 기반의 파이썬 코드로 작성되어 있으며, 코드 컨벤션 및 정적 분석(`flake8`)을 통해 확인했습니다.

### 2-1. 정적 코드 분석 (`flake8`)
결과: 다수의 스타일 및 잠재적 로직 버그 감지
* **[Logic] f-string 누락 (오류 가능성)**
  * `app/engine/services/api_service.py` 138라인, 884라인 등 다수의 로깅 및 에러 메시지 작성 부에서 변수가 포맷팅되지 않고 일반 문자열로 취급되고 있습니다. (예: `f"..."` 형태가 아닌 `"{variable}"` 형태로 작성되어 문자열 그대로 노출됨)
* **[Logic] 캡처만 하고 처리하지 않는 `except`**
  * `app/dependencies.py` 등의 파일에서 `except:` (`E722`)와 같이 구체적이지 못한 예외 처리가 있어, 의도치 않은 시스템 오류나 키보드 인터럽트까지 묻힐 가능성이 존재합니다.
* **[Logic] 미사용 선언 변수 및 Import**
  * `F401`: `app.database.engine`, `asyncio`, `pygame` 관련 모델 등 사용되지 않는 모듈이 임포트 되어 있습니다.
  * `F841`: `is_holiday_val`, `response_text`, `e` 등 값을 반환받거나 할당해 놓고 아무 작업도 처리하지 않은 잉여 변수 존재.
* **[Style] PEP8 컨벤션 불일치**
  * `E501 (Line too long)` 및 `W293 (Blank line contains whitespace)`가 `models.py`를 포함한 거의 전 파일에 수백 건 존재하여 리팩토링이나 Black과 같은 Formatter 적용이 시급합니다.

### 2-2. 보안 및 인증 점검 코멘트
* **API Key 및 JWT 혼용 처리 로직** (`app/routers/api.py` 내 `get_current_user_or_api_key`) ⭐⭐⭐⭐⭐
  * 현재 헤더의 `X-API-KEY` 검증과 사용자 토큰이 동시에 작동하고 있습니다. 비교 시 `.strip()` 처리를 추가한 것은 좋으나, 토큰 유효성 검사에서 누수(Leak)나 우회(Bypass)가 없는지 시크릿 키 관리(Secret Key Rotation) 전략 재검토가 권장됩니다.

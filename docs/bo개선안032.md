## 1. 문서 목적과 범위

### 1-1. 목적

- 백오피스(Admin) **정보 구조(메뉴)** 를 운영 업무에 맞게 재정렬한다.  
- **이벤트·등급 자동화** 로 회원 운영 비용을 줄이고, 추후 마케팅·알림 정책 확장의 토대를 만든다.

### 1-2. 범위 안 (In scope)

- `apps/admin` 대시보드 UI, FastAPI 라우터, SQLAlchemy 모델, 스케줄러.  
- 본 문서의 Phase별 항목 구현.

### 1-3. 범위 밖 (Out of scope) — 명시적 제외

- **웹/앱 클라이언트(`web_new`, 모바일)** 의 화면 대개편(이벤트 배너 노출 등은 별도 기획으로 연동 필요 시 명시).  
- 결제·쿠폰·정산 시스템.  
- 외부 CDP/CRM 연동.

### 1-4. 연동 시 유의

- 회원 등급·이벤트 혜택이 **공개 REST API(`app/routers/api.py` 등)** 및 **web_new** 에 반영되는 경우, 동일 규칙(예: `get_effective_grade()`)을 재사용할지 명시하고 중복 로직을 피할 것.

## 2. 용어 및 설계 원칙

| 용어 | 설명 |
|------|------|
| 이벤트(Event) | 기간·조건·참여 한도가 있는 **캠페인 단위** 혜택. `EventParticipation`으로 참여 이력 관리. |
| 등급 정책(GradePolicy) | **스케줄러 또는 수동**에 가깝게, 규칙 기반으로 등급을 부여·연장하는 정책. `GradePolicyLog`로 이력 관리. |
| 주BTI | `members.jubti_type` 등으로 완료 여부를 판단하는 온보딩 성향 테스트. |

**원칙**

1. **단일 진실 공급원**: 등급의 “유효 등급” 계산은 기존 `get_effective_grade()` 등 한 경로로 통일하고, 이벤트/정책은 그 경로를 호출하거나 동일 DB 필드를 갱신만 한다.  
2. **멱등성**: 혜택 적용·스케줄러는 재실행해도 중복 지급이 나지 않도록 `Participation` / `Log` / `upgrade_once` 로 제어한다.  
3. **시간대**: 스케줄 시각은 문서상 **KST(Asia/Seoul)** 기준으로 명시하고, DB에는 `timestamptz` 권장.  
4. **감사 가능성**: 등급·이벤트 적용은 로그 테이블에 남긴다.

## 5. 이벤트 정책 설정

### 5-1. 개요

회원 유치·전환·유지를 위한 **시간·조건 기반 캠페인**을 관리자가 설계·운영한다.

### 5-2. 이벤트 유형

| 유형 코드 | 설명 | 예시 |
|-----------|------|------|
| `join_welcome` | 가입 환영 | 가입 후 7일 VIP 무료 체험 |
| `activity_reward` | 활동 보상 | 게시글 5개 작성 시 VIP 1개월 |
| `period_promo` | 기간 한정 프로모션 | 설 연휴 VIP 50% 할인 |
| `jubti_reward` | 주BTI 완료 보상 | 주BTI 완료 시 VIP 2주 |
| `referral` | 친구 초대 보상 | 추천인·피추천인 모두 VIP 1주 |

### 5-3. DB 모델 (신규) — 초안

> 구현 시 `app/engine/models.py` 및 마이그레이션으로 반영. PostgreSQL이면 `JSON`/`JSONB` 호환 타입 사용.  
> 테이블명 `events`는 일부 환경에서 혼동될 수 있어, 필요 시 `bo_events` 등 접두 검토.

```python
class Event(Base):
    __tablename__ = "events"

    id               = Column(Integer, primary_key=True)
    name             = Column(String(100), nullable=False)
    event_type       = Column(String(30), nullable=False)
    description      = Column(Text, nullable=True)
    start_date       = Column(DateTime(timezone=True), nullable=True)  # null=즉시
    end_date         = Column(DateTime(timezone=True), nullable=True)  # null=무기한
    is_active        = Column(Boolean, default=True)
    max_participants = Column(Integer, nullable=True)

    benefit_type     = Column(String(20), nullable=False)  # 'grade_upgrade' | 'grade_extend'
    benefit_grade    = Column(String(20), default="vip")
    benefit_days     = Column(Integer, nullable=False)

    trigger_condition = Column(JSON, nullable=True)

    created_at       = Column(DateTime(timezone=True), server_default=func.now())
    updated_at       = Column(DateTime(timezone=True), onupdate=func.now())


class EventParticipation(Base):
    __tablename__ = "event_participations"

    id               = Column(Integer, primary_key=True)
    event_id         = Column(Integer, ForeignKey("events.id"), nullable=False)
    member_id        = Column(Integer, ForeignKey("members.id"), nullable=False)
    participated_at  = Column(DateTime(timezone=True), server_default=func.now())
    benefit_applied  = Column(Boolean, default=False)
    benefit_expires  = Column(DateTime(timezone=True), nullable=True)

    __table_args__ = (
        UniqueConstraint("event_id", "member_id", name="uq_event_member"),
    )
```

**등록 폼 항목**

- 혜택: 등급(VIP/Family) + 기간(일)  
- 발동 조건 (유형별 동적 필드)  
- 활성/비활성 토글  

### 5-5. 발동 처리 흐름

```
[회원 액션]
       ↓
EventTriggerService.check(member, action)
       ↓
활성 이벤트 중 조건 일치
       ↓
EventParticipation 중복 검사 (유니크)
       ↓
혜택 적용 (member.grade / grade_expires_at 등)
       ↓
FCM (정책에 따라 — §8 알림 정책 연동 시 on/off)
```

**발동 시점**

| 유형 | 시점 |
|------|------|
| `join_welcome` | 가입 완료 직후 |
| `activity_reward` | 게시글 작성 완료 등 (투표 연계 시 §8-7) |
| `jubti_reward` | 주BTI 결과 저장 직후 |
| `period_promo` | 스케줄러(예: 매일 00:05 KST)로 기간·조건 재평가 |
| `referral` | 초대 관계 확정 시 (구현 시 API 지점 정의) |

## 6. 회원 등급 승급 기준

### 6-1. 현재 상태

- 등급: `regular` / `vip` / `family`  
- 변경: 관리자 수동 `/admin/members/grade/{id}`  
- 자동화: 만료 체크 위주 (`get_effective_grade()`), **자동 승급 규칙 없음**

### 6-2. 등급 정책 모델 (신규) — 초안

```python
class GradePolicy(Base):
    __tablename__ = "grade_policies"

    id               = Column(Integer, primary_key=True)
    name             = Column(String(100), nullable=False)
    target_grade     = Column(String(20), nullable=False)  # 'vip' | 'family'
    is_active        = Column(Boolean, default=True)
    is_auto          = Column(Boolean, default=False)

    condition_type   = Column(String(30), nullable=False)
    conditions_json  = Column(JSON, nullable=True)

    benefit_days     = Column(Integer, nullable=True)
    upgrade_once     = Column(Boolean, default=True)

    description      = Column(Text, nullable=True)
    created_at       = Column(DateTime(timezone=True), server_default=func.now())
    updated_at       = Column(DateTime(timezone=True), onupdate=func.now())
```

### 6-3. 조건 유형

| condition_type | 파라미터 예 | 설명 |
|----------------|------------|------|
| `join_days` | `{"days": 30}` | 가입 후 n일 경과 |
| `post_count` | `{"count": 10}` | 누적 게시글 n개 이상 |
| `login_days` | `{"days": 7, "period": 30}` | 최근 period일 내 distinct 로그인일 n일 이상 — **구현 전 `login` 이벤트 저장 여부 검증 필요** |
| `jubti_complete` | `{}` | `jubti_type IS NOT NULL` |
| `favorite_count` | `{"count": 5}` | 관심종목 n개 이상 |
| `composite` | `{"operator": "AND"\|"OR", "rules": [...]}` | 복합 |

### 6-4. 관리자 UI (신규: `/admin/grade-policies`)

(목록·폼 UX는 §5-4와 동일 패턴: 목록 테이블 + 편집 화면)

### 6-5. 자동 승급 스케줄러

- 예: **매일 02:00 KST** `GradePolicyScheduler`  
- `is_active`·`is_auto` 로드 → 정책별 대상 회원 산출 → `upgrade_once` 이미 적용 분 제외 → 등급·만료 반영 → `GradePolicyLog` → FCM은 알림 정책(§8-4)과 연동

### 6-6. 등급 정책 이력

```python
class GradePolicyLog(Base):
    __tablename__ = "grade_policy_logs"

    id              = Column(Integer, primary_key=True)
    policy_id       = Column(Integer, ForeignKey("grade_policies.id"), nullable=False)
    member_id       = Column(Integer, ForeignKey("members.id"), nullable=False)
    before_grade    = Column(String(20))
    after_grade     = Column(String(20))
    applied_at      = Column(DateTime(timezone=True), server_default=func.now())
    expires_at      = Column(DateTime(timezone=True), nullable=True)
    trigger_source  = Column(String(20), default="auto")  # 'auto' | 'manual' | 'event'
```

## 7. 이벤트 × 등급 정책 — 충돌 방지

| 시나리오 | 권장 처리 |
|----------|-----------|
| 동일 회원이 같은 날 이벤트와 등급 정책 모두 충족 | **우선순위 규칙**을 코드에 명문화 (예: 이벤트 > 정책, 또는 더 높은 등급만 적용). 문서·운영 가이드에 한 줄로 고정. |
| `benefit_extend` vs 신규 `grade_upgrade` | 만료일 연장과 등급 변경이 겹치면 **한 트랜잭션**에서 최종 `grade`·`grade_expires_at` 계산. |
| 스케줄러와 실시간 트리거 동시 실행 | DB 락 또는 `SELECT … FOR UPDATE` / 유니크 로그로 **이중 적용 방지**. |

class NotificationPolicy(Base):

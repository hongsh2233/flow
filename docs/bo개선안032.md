## 3. 이벤트 정책 설정

### 3-1. 개요

회원 유치·전환·유지를 위한 시간 한정 이벤트를 관리자가 직접 설계·운영할 수 있는 체계.

### 3-2. 이벤트 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| `join_welcome` | 가입 환영 이벤트 | 가입 후 7일 VIP 무료 체험 |
| `activity_reward` | 활동 보상 이벤트 | 게시글 5개 작성 시 VIP 1개월 |
| `period_promo` | 기간 한정 프로모션 | 설 연휴 VIP 50% 할인 |
| `jubti_reward` | 주BTI 완료 보상 | 주BTI 테스트 완료 시 VIP 2주 |
| `referral` | 친구 초대 보상 | 추천인·피추천인 모두 VIP 1주 |

### 3-3. DB 모델 (신규)

```python
class Event(Base):
    __tablename__ = "events"

    id              = Column(Integer, primary_key=True)
    name            = Column(String(100), nullable=False)   # 이벤트명
    event_type      = Column(String(30), nullable=False)    # 위 유형 코드
    description     = Column(Text, nullable=True)           # 설명
    start_date      = Column(DateTime, nullable=True)       # 시작일 (null=즉시)
    end_date        = Column(DateTime, nullable=True)       # 종료일 (null=무기한)
    is_active       = Column(Boolean, default=True)
    max_participants= Column(Integer, nullable=True)        # 최대 참여자 수 (null=무제한)

    # 혜택 정의
    benefit_type    = Column(String(20), nullable=False)    # 'grade_upgrade' | 'grade_extend'
    benefit_grade   = Column(String(20), default='vip')    # 부여할 등급
    benefit_days    = Column(Integer, nullable=False)       # 혜택 기간 (일)

    # 발동 조건 (JSON)
    # 예: {"type": "post_count", "threshold": 5}
    # 예: {"type": "join_within_days", "days": 1}
    # 예: {"type": "jubti_complete"}
    trigger_condition = Column(JSON, nullable=True)

    created_at      = Column(DateTime, server_default=func.now())
    updated_at      = Column(DateTime, onupdate=func.now())


class EventParticipation(Base):
    __tablename__ = "event_participations"

    id              = Column(Integer, primary_key=True)
    event_id        = Column(Integer, ForeignKey("events.id"), nullable=False)
    member_id       = Column(Integer, ForeignKey("members.id"), nullable=False)
    participated_at = Column(DateTime, server_default=func.now())
    benefit_applied = Column(Boolean, default=False)    # 혜택 적용 여부
    benefit_expires = Column(DateTime, nullable=True)   # 혜택 만료일

    __table_args__ = (
        UniqueConstraint('event_id', 'member_id', name='uq_event_member'),
    )
```

### 3-4. 관리자 UI (신규 페이지: `/admin/events`)

```
┌─────────────────────────────────────────────────┐
│  이벤트 정책 관리                  [+ 이벤트 추가] │
├─────────────────────────────────────────────────┤
│  이벤트명  │ 유형  │ 기간       │ 참여  │ 상태   │
│  ─────────────────────────────────────────────  │
│  가입 VIP  │ 환영  │ 상시       │ 142명 │ [활성] │
│  설 프로모 │ 기간  │ ~02/05     │  38명 │ [종료] │
│  주BTI 보상│ 활동  │ 상시       │  67명 │ [활성] │
└─────────────────────────────────────────────────┘
```

**이벤트 등록 폼 항목:**
- 이벤트명, 유형 선택
- 시작일·종료일 (비워두면 상시)
- 최대 참여 인원 (비워두면 무제한)
- 혜택: 등급(VIP/Family) + 기간(일)
- 발동 조건 설정 (유형별 파라미터 동적 표시)
- 활성/비활성 토글

### 3-5. 이벤트 발동 처리 흐름

```
[회원 액션 발생]
       ↓
[EventTriggerService.check(member, action)]
       ↓
[활성 이벤트 중 조건 일치 검색]
       ↓
[EventParticipation 중복 확인]
       ↓
[혜택 적용: member.grade 변경 + grade_expires_at 설정]
       ↓
[FCM 알림: "축하합니다! VIP 혜택이 지급되었습니다."]
```

발동 체크 시점:
- 가입 완료 후 (`join_welcome`)
- 게시글 작성 완료 후 (`activity_reward`)
- 주BTI 결과 저장 후 (`jubti_reward`)
- 스케줄러: 매일 00:00 기간한정 이벤트 점검 (`period_promo`)

## 4. 회원 등급 승급 기준

### 4-1. 현재 상태

- 등급: `regular` / `vip` / `family`
- 변경: 관리자가 수동으로 `/admin/members/grade/{id}` 에서만 변경 가능
- 자동화: 만료 체크만 있음 (`get_effective_grade()`)
- **자동 승급 기준 없음**

### 4-2. 등급 정책 모델 (신규)

```python
class GradePolicy(Base):
    """
    회원 등급 자동 승급 기준 정책.
    is_auto=True이면 스케줄러가 매일 조건을 검사하여 자동 적용.
    """
    __tablename__ = "grade_policies"

    id              = Column(Integer, primary_key=True)
    name            = Column(String(100), nullable=False)   # 정책명
    target_grade    = Column(String(20), nullable=False)    # 부여 등급: 'vip' | 'family'
    is_active       = Column(Boolean, default=True)
    is_auto         = Column(Boolean, default=False)        # 자동 적용 여부

    # 조건 유형
    condition_type  = Column(String(30), nullable=False)
    # 'join_days'       : 가입 후 n일 이상 활동 회원
    # 'post_count'      : 누적 게시글 n개 이상
    # 'login_days'      : 최근 30일 내 n회 이상 로그인
    # 'jubti_complete'  : 주BTI 완료 여부
    # 'composite'       : 복합 조건 (conditions_json 참조)

    conditions_json = Column(JSON, nullable=True)
    # 예 (join_days):   {"days": 30}
    # 예 (post_count):  {"count": 10}
    # 예 (composite):   {"operator": "AND", "rules": [{"type": "join_days", "days": 30}, {"type": "post_count", "count": 5}]}

    # 혜택
    benefit_days    = Column(Integer, nullable=True)        # 승급 기간 (null=무기한)
    upgrade_once    = Column(Boolean, default=True)         # 1회만 적용 여부

    description     = Column(Text, nullable=True)           # 정책 설명 (관리자 메모)
    created_at      = Column(DateTime, server_default=func.now())
    updated_at      = Column(DateTime, onupdate=func.now())
```

### 4-3. 조건 유형 상세

| condition_type | 파라미터 | 설명 |
|---------------|---------|------|
| `join_days` | `{"days": 30}` | 가입 후 30일 이상 경과 |
| `post_count` | `{"count": 10}` | 누적 게시글 10개 이상 작성 |
| `login_days` | `{"days": 7, "period": 30}` | 최근 30일 내 7일 이상 로그인 |
| `jubti_complete` | `{}` | 주BTI 테스트 완료 (jubti_type IS NOT NULL) |
| `favorite_count` | `{"count": 5}` | 관심종목 5개 이상 등록 |
| `composite` | `{"operator": "AND"/"OR", "rules": [...]}` | 복합 조건 |

### 4-4. 관리자 UI (신규 페이지: `/admin/grade-policies`)

```
┌──────────────────────────────────────────────────────┐
│  등급 정책 관리                      [+ 정책 추가]    │
├──────────────────────────────────────────────────────┤
│  정책명          │ 대상등급 │ 조건           │ 자동 │
│  ──────────────────────────────────────────────────  │
│  30일 활동 VIP   │ VIP     │ 가입 30일+      │ ✅  │
│  게시왕 VIP      │ VIP     │ 게시글 10개+    │ ✅  │
│  주BTI 완료 보상 │ VIP     │ 주BTI 완료      │ ✅  │
│  우수회원 Family │ Family  │ AND(60일+, 20글)│ ✅  │
│  수동 지정 VIP   │ VIP     │ 수동            │ ❌  │
└──────────────────────────────────────────────────────┘
```

**정책 등록 폼 항목:**
- 정책명, 대상 등급 (VIP / Family)
- 조건 유형 선택 → 유형별 파라미터 입력 UI 동적 렌더링
- 복합 조건: AND/OR 선택 + 규칙 추가/삭제
- 혜택 기간 (일 단위, 비워두면 무기한)
- 1회 적용 여부 (매번 갱신 vs 최초 1회)
- 자동 적용 여부 토글
- 설명/메모

### 4-5. 자동 승급 스케줄러 흐름

```
[매일 02:00 KST - GradePolicyScheduler]
       ↓
[is_active=True, is_auto=True 정책 전체 로드]
       ↓
  [각 정책에 대해]
       ↓
[대상 회원 필터링: upgrade_once=True이면 이미 적용된 회원 제외]
       ↓
[조건 충족 회원 검색 (SQL 쿼리 or Python 로직)]
       ↓
[member.grade 변경 + grade_expires_at 설정]
       ↓
[FCM: "등급이 [VIP]로 업그레이드 되었습니다!"]
       ↓
[GradePolicyLog 기록]
```

```python
class GradePolicyLog(Base):

    after_grade     = Column(String(20))

    expires_at      = Column(DateTime, nullable=True)
    trigger_source  = Column(String(20), default='auto')  # 'auto' | 'manual' | 'event'
```

### 5-4. 알림 정책 설정 (신규: `/admin/notification-policy`)

현재: FCM 발송 로직이 서비스 코드에 하드코딩
개선:

```python
class NotificationPolicy(Base):
    __tablename__ = "notification_policies"

    id              = Column(Integer, primary_key=True)
    policy_key      = Column(String(50), unique=True)
    # 예: 'morning_briefing', 'schedule_alert', 'grade_upgrade', 'new_post'

    is_enabled      = Column(Boolean, default=True)   # 전체 on/off
    send_fcm        = Column(Boolean, default=True)   # FCM 발송 여부
    send_inapp      = Column(Boolean, default=True)   # 인앱 알림 여부
    title_template  = Column(String(200))             # 제목 템플릿 ({변수} 치환)
    body_template   = Column(Text)                    # 본문 템플릿
    description     = Column(String(200))             # 관리자 설명
```

관리자 UI:
- 알림 유형별 on/off 토글
- FCM / 인앱 각각 토글
- 메시지 템플릿 편집 (제목·본문)
- 테스트 발송 버튼 (관리자 계정으로 샘플 발송)

# 인포스탁(Infostock) 증시 캘린더 스크래핑 타당성 검토

## 1. 페이지 구조 및 접근성
- **URL**: `https://infostock.co.kr/EventNews/Month` (월간/주간 이슈 & 테마 스케줄 페이지)
- **프레임워크**: Vue.js 기반의 **Nuxt.js** (SPA 프레임워크)를 사용하여 렌더링되고 있습니다.
- **데이터 로딩 방식**: SSR(Server-Side Rendering) 및 클라이언트 사이드 AJAX/Fetch 요청으로 캘린더 데이터를 JSON 형태로 불러오는 구조입니다.

## 2. 보안 및 제약 사항 (Scraping Hurdles)
브라우저 봇을 통해 화면 접근 및 렌더링 과정을 테스트한 결과, 캘린더 내용 자체는 난독화되어 있지 않으나 **권한 제약(Paywall)**이 존재합니다.
- **무료/비로그인 유저**: 당일 혹은 다음 달 등 핵심 '미래 일정' 데이터에 대해 접근이 차단되거나, 일정 조회 시 **유료 회원 결제 유도 모달 / 로그인 창**이 나타납니다.
- 실제 달력 UI 틀은 불러와지지만, 내용(일정 텍스트)이 비워진 채로 서빙되는 것을 확인했습니다. (봇 캡처 확인 결과 빈 달력만 표시됨)

## 3. 스크래핑 구현 가능성 및 전략
결론적으로 **기술적인 스크래핑(크롤링) 자체는 가능하나, 유효한 데이터를 얻으려면 유료 파싱 방식을 적용해야 합니다.**

### 3-1. 수집 방법론 (Python / Node.js)
만약 로그인 정보를 제공할 수 있다면 다음 방법으로 스크래핑이 가능합니다.
1. **API 직접 호출 패턴 (권장, Python `requests` 또는 JS `axios`)**
   - 브라우저 개발자 도구의 Network 탭에서 로그인 후 달력을 넘길 때 호출되는 JSON API (예: `/api/schedule/month?date=...`)의 엔드포인트를 찾아 직접 호출합니다. 
   - HTTP Header에 세션 쿠키(`Cookie`)나 JWT 인증 토큰을 삽입하여 봇이 아닌 일반 회원인 것처럼 요청을 변조합니다.
2. **Headless Browser (Playwright / Selenium)**
   - API가 복잡하게 암호화되어 있거나 세션 유지가 까다로운 경우, Python/Node.js Playwright를 이용해서 실제 유저처럼 로그인한 뒤 달력 페이지에 접속하여 DOM 트리의 Table 텍스트(`<td>`, `<li>`)를 파싱해옵니다.

### 3-2. 유의사항
- **계정 밴(Ban)**: 하나의 유료 계정으로 지나치게 빠른 속도(1초에 여러 번)로 일정을 긁어올 경우, 인포스탁 측에서 '다중 접속'이나 '비정상 트래픽'으로 간주하여 계정을 정지할 위험이 있습니다. 딜레이(Delay) 설정이 필수적입니다.
- **대안 데이터 소스**: 단순히 주요 상장 일정 및 경제 지표라면 네이버 증권(사용 중이신 API), 한국거래소(KRX), Investing.com 캘린더 등 무료로 열려 있는 대체 API를 이용하는 것이 리스크와 비용 측면에서 유리할 수 있습니다.
